> 上游依据：ANIM-2 需求设计定稿 v1.0（D3 牢房互动三类基础、D4 每日上限、D6 时间边缘辅助、M3/M4/M6/M7 模块）；ANIM-16 数值基线 v1.0（锁定，本文所有数值均引用该基线，未改动已锁结论）。
> 受众：M4（食堂/餐食）/ M6（评分）/ M7（满意度）开发；T2.3 happy path 与 T2.4 异常分支 E2E 用例；动画/UX；`/api/interaction` mock 对齐。

## 0. 总览与全局规则

| 项 | 规则 | 来源 |
|---|---|---|
| 互动入口 | 每只动物独立牢房页（M3 地图系统），页面提供「喂食 / 放风 / 陪玩」三个互动按钮 | 定稿 v1.0 D3 / M3 |
| 权威侧 | 频次、时段、ΔS、行为分、日切全部**服务端权威**；客户端仅做展示与交互（客户端时区不参与计算） | 定稿 v1.0 风险 3；基线 §2.5 |
| 日切 | **UTC+8 00:00**；跨日切客户端静默刷新按钮剩余次数 | 基线 §2.5 |
| 每日频次上限（日/只） | 喂食 ≤3 / 放风 ≤2 / 陪玩 ≤3（**与基线 §1.2/§2.5 一致，无修订**） | 基线 v1.0 |
| 满意度/评分影响 | ΔS 与行为分数值**全部引用基线**（本文 §3 各节引用 §1.2/§2.2/§1.4），不新增数值实体 | 基线 v1.0 |
| 防重 | 每次提交携带 `requestId`（客户端生成），服务端幂等去重；同动物同类型互动在途时按钮置灰 | 本文新增（实现约束，不改数值） |

互动通用结构（三类共用）：
1. 点按牢房页互动按钮 → 客户端前置校验（时段提示 / 剩余次数）；
2. 选择子项（食物 / 玩具，放风无子项）→ 提交 `POST /api/interaction`；
3. 播放互动动画（3–10s，可跳过/2×）→ 展示结果卡（ΔS、行为分、规则语料气泡）；
4. 更新按钮角标（今日剩余次数），结果落库由服务端完成。

## 1. 喂食（硬时段门控）

### 1.1 操作流程（客户端）
1. 牢房页点按「喂食」；
2. **时段判定（硬门控，服务端权威复核）**：
   - 处于 3 个餐食时段之一（07:00–09:00 / 11:30–13:00 / 17:30–19:00，UTC+8）→ 进入食物选择；
   - 非时段 → Toast「食堂未开饭，下一餐 {时段起}–{时段止}」，不进入选择、不消耗次数（分支 F1）；
3. 食物选择面板：列出**当前餐食时段食堂供应的 1–3 种食物**（来自食堂 M4 的时段供应配置），每种带「喜欢 / 讨厌 / 普通」三态标记（按动物喜厌配置，M7）；
4. 点按食物确认 → 提交 `POST /api/interaction` `{ animalId, action:"feed", foodId, requestId }`；
5. 播放进食动画（3s）→ 结果卡：ΔS、行为分、规则语料气泡（M8/ANIM-15 内容）；
6. 按钮角标 -1。

讨厌食物**可选且带标记**：选中「讨厌」食物直接确认（无二次确认，标记已足够提示），产生基线中的负向/降权收益（分支 F3）。

### 1.2 耗时 / 冷却 / 频次
| 项 | 值 | 说明 |
|---|---|---|
| 单次耗时 | 交互 ≤10s；动画 3s（可跳过） | 非阻塞：提交后离开页面，结果自动落库，下次进牢房页/动物卡片红点提示 |
| 冷却 | 无全局 CD；同动物在途动画期间按钮置灰（防手抖连点，1–3s） | 客户端体验约束 |
| 频次 | 每日 ≤3 次/只；每餐食时段至多 1 次（服务端按时段+计数双重校验） | = 基线 §1.2 频次上限（3 个餐食时段） |
| 可玩时间 | 仅 3 个餐食时段（硬门控） | 基线 §2.2 |

### 1.3 满意度与评分影响（引用基线，无新增）
- ΔS = +6 × 喜好(×1.5/×0.5) × 性格 k，计入单只每日收益上限 +15（基线 §1.2）；
- 喂到讨厌食物：可选 −2（按动物配置，基线 §1.2 负向项）；
- 行为分 = 5 × 1.5（餐食时段 w_t）× c_S（满意度档位系数，基线 §1.4），计入单只每日行为分上限 50（基线 §2.2）；
- 示例（猫，k=1.0，全喜好，高满意度 c_S=1.2）：3 次喂食 ΔS 27 → 截断 +15；行为分 3×9=27。

### 1.4 动画 / 反馈
| 分支 | 条件 | 反馈形式 | 动画 | 服务端错误码（建议） |
|---|---|---|---|---|
| F0 成功 | 时段内 + 次数可用 | 结果卡（ΔS +N / 行为分 +M）+ 语料气泡 | 进食 3s，喜欢食物表情正向 | `200 { ok, deltaS, points, remaining }` |
| F1 非时段 | 不在 3 个餐食时段 | Toast「食堂未开饭…」+ 下一餐时间 | 无（按钮常态可用，点击才提示） | `INTERACTION_NOT_IN_WINDOW` |
| F2 已达上限 | 当日已 3 次（含跨时段） | Toast「今天已喂 3 次，00:00 重置」 | 无 | `INTERACTION_DAILY_LIMIT` |
| F3 讨厌食物 | foodId ∈ 动物讨厌表 | 结果卡 ΔS −2（或 ×0.5 降权）+「似乎不太喜欢…」语料 | 进食但表情负向动画 | `200`（收益为负/降权，非错误） |
| F4 重复提交 | requestId 重复 / 在途 | 幂等去重或 Toast「互动进行中」 | 无 | 幂等返回原结果 / `INTERACTION_IN_PROGRESS` |
| F5 服务端异常 | 其余失败 | Toast「提交失败，请重试」+ 重试按钮 | 无 | `INTERACTION_FAILED` |

## 2. 放风（软时段降权）

### 2.1 操作流程（客户端）
1. 牢房页点按「放风」（全天候可进，无子项选择）；
2. 时段判定（软门控）：
   - 建议时段 15:00–17:00（UTC+8）→ 直接提交；
   - 非建议时段 → 提示弹窗「非放风建议时段，收益降权（w_t 1.2→1.0），继续？」，确认后提交（分支 R1）；
3. 提交 `POST /api/interaction` `{ animalId, action:"exercise", requestId }`；
4. 放风场（运动场）场景动画 10s（可 2× 跳过至 5s）→ 结果卡 + 语料气泡；
5. 按钮角标 -1。

### 2.2 耗时 / 冷却 / 频次
| 项 | 值 | 说明 |
|---|---|---|
| 单次耗时 | 动画 10s（2× 可跳）；非阻塞 | 离开页面后结果自动落库 + 红点提示 |
| 冷却 | 无全局 CD；在途动画期间按钮置灰 | — |
| 频次 | 每日 ≤2 次/只（服务端计数） | = 基线 §1.2，无修订 |
| 可玩时间 | 全天；15:00–17:00 为建议时段 | 基线 §2.2 |

### 2.3 满意度与评分影响（引用基线，无新增）
- ΔS = +5 × 喜好（互动类喜厌）× k，计入每日 +15 上限（基线 §1.2）；
- 行为分 = 5 × w_t（建议时段 1.2 / 非时段 1.0）× c_S，计入每日 50 上限（基线 §2.2）；
- 示例（狗，k=0.9，高满意度 c_S=1.2，建议时段）：ΔS +5×0.9=+4.5/次；行为分按基线公式 5×w_t×c_S = 5×1.2×1.2 = 7.2/次（k 仅作用于 ΔS）。

### 2.4 动画 / 反馈
| 分支 | 条件 | 反馈形式 | 动画 | 服务端错误码 |
|---|---|---|---|---|
| R0 成功（建议时段） | 15:00–17:00 | 结果卡（标注 w_t 1.2）+ 语料气泡 | 运动场 10s | `200` |
| R1 成功（非时段降权） | 其余时间 | 提交前降权提示 + 结果卡（标注 w_t 1.0） | 同上 | `200`（w_t 按 1.0 结算） |
| R2 已达上限 | 当日已 2 次 | Toast「今天放风 2 次已满，00:00 重置」 | 无 | `INTERACTION_DAILY_LIMIT` |
| R3 重复/异常 | 同 F4/F5 | 同 F4/F5 | 无 | 同上 |

## 3. 陪玩（轻 QTE + 软硬时段）

### 3.1 操作流程（客户端）
1. 牢房页点按「陪玩」；
2. 玩具选择：列出**该动物可用玩具 1–3 种**（动物性格配置表，按 M7），带「喜欢/讨厌/普通」标记；
3. 轻互动（QTE）：**5s 内点按玩具 3 下** → 完成 1 次互动提交；5s 内未点满 3 下 → 「小家伙走神了」，次数**不消耗**、可立即重玩（零成本，分支 P2）；
4. 时段提示（软）：夜间 22:00–07:00 提交前提示「夜间陪玩收益降权（w_t 1.0→0.8）」（分支 P1）；白天 10:00–22:00 无提示；07:00–10:00 为白天系数 1.0 的普通时段；
5. 提交 `POST /api/interaction` `{ animalId, action:"play", toyId, requestId }`（仅在 QTE 完成后提交一次）；
6. 玩耍动画 5s → 结果卡 + 语料气泡；按钮角标 -1。

### 3.2 耗时 / 冷却 / 频次
| 项 | 值 | 说明 |
|---|---|---|
| 单次耗时 | QTE 5s + 动画 5s；未点满不计时消耗 | 非阻塞 |
| 冷却 | 无全局 CD；QTE 重玩无冷却（零成本）；在途动画期间按钮置灰 | 与喂食/放风一致 |
| 频次 | 每日 ≤3 次/只（服务端计数，QTE 失败不计次） | = 基线 §1.2，无修订 |
| 可玩时间 | 全天；10:00–22:00 w_t 1.0，22:00–07:00 w_t 0.8 | 基线 §2.2 |

### 3.3 满意度与评分影响（引用基线，无新增）
- ΔS = +5 × 玩具喜好(×1.5/×0.5) × k，计入每日 +15 上限（基线 §1.2）；
- 行为分 = 5 × w_t（1.0/0.8）× c_S，计入每日 50 上限（基线 §2.2）；
- 示例（猫，k=1.1，喜欢夜间陪玩，夜间）：ΔS +7.5；行为分 5×0.8×c_S。

### 3.4 动画 / 反馈
| 分支 | 条件 | 反馈形式 | 动画 | 服务端错误码 |
|---|---|---|---|---|
| P0 成功（白天） | 07:00–22:00（w_t 1.0） | 结果卡 + 语料气泡 | 玩耍 5s | `200` |
| P1 成功（夜间降权） | 22:00–07:00 | 提交前降权提示 + 结果卡（标注 w_t 0.8） | 同上 | `200` |
| P2 QTE 未达 | 5s 内未点满 3 下 | 提示「小家伙走神了，再试试」 | 动物走神短动画（1s） | 不提交 |
| P3 已达上限 | 当日已 3 次 | Toast「今天陪玩 3 次已满，00:00 重置」 | 无 | `INTERACTION_DAILY_LIMIT` |
| P4 重复/异常 | 同 F4/F5 | 同 F4/F5 | 无 | 同上 |

## 4. 反馈汇总（E2E 用例映射）

三类共用的状态/反馈规则：
- 结果卡统一结构：`ΔS +N（或 −N）`、`行为分 +M（标注 w_t）`、语料气泡一句（M8/ANIM-15 内容，本文只预留位）；
- 按钮角标恒显「今日剩余 n 次」，n=0 时按钮置灰但可点（点击出 Toast 提示重置时间）；
- 日切跨 00:00：客户端静默重拉 `/api/rating` 与剩余次数；当日无任何照顾行为时，动物卡片展示满意度变化（−2×d）轻提示（基线 §1.3 衰减的可见化，文案「小家伙有点想你」）。

**T2.3 happy path 用例映射**：
| 用例 | 步骤 | 断言点 |
|---|---|---|
| 喂食成功 | 餐食时段内 → 选食物 → 提交 | 结果卡 ΔS/行为分正确；`/api/rating` S、P 更新；角标 -1 |
| 放风成功 | 15:00–17:00 内提交 | w_t 1.2 生效；P 增量 = 5×1.2×c_S |
| 陪玩成功 | 白天 QTE 3 下 → 提交 | 结果卡正确；角标 -1 |

**T2.4 异常分支用例映射**：
| 用例 | 分支 | 断言点 |
|---|---|---|
| 非时段喂食 | F1 | Toast 展示；不计数（剩余次数不变）；错误码 `INTERACTION_NOT_IN_WINDOW` |
| 达上限 | F2/R2/P3 | Toast「00:00 重置」；错误码 `INTERACTION_DAILY_LIMIT`；不计数 |
| 非时段降权 | R1/P1 | 提交成功且 w_t 降权生效（P 增量按降权值） |
| 重复提交 | F4/R3/P4 | requestId 幂等：S/P 不双计 |
| 讨厌食物/玩具 | F3/P0(×0.5) | ΔS 按 ×0.5/−2 结算，非错误码 |

## 7. 开放问题 / 风险（不阻塞，供排期参考）

1. **食物/玩具具体条目表**：本文只定义「喜欢/讨厌/普通」三态标记机制，逐物种条目由游戏侧在动物性格配置表填写（示例：猫-罐头/狗-球，见基线 §1.5 示例）。
2. **语料内容**：结果卡气泡内容归 ANIM-15/M8（规则语料触发条件已含「近期互动」），本文仅预留展示位与去重要求（同条件不重复同一句）。
3. **动画资源**：进食 3s / 运动场 10s（2×）/ 玩耍 5s / 走神 1s 四段为时长规格；具体美术资产由美术侧出清单。
4. **QTE 可玩性**：5s×3 下为首版轻量方案；若测试反馈无趣，备选「节奏点按」仍不占频次（QTE 失败零成本的设计已为此预留），属 P2 迭代。
5. **夜间提示粒度**：07:00–10:00 陪玩按白天 1.0 处理（基线时段表的自然推论），如需更细分档需修订基线 §2.2 时段表（届时按 ANIM-16 流程回流）。
