## 0. 术语与依赖对齐（关键，避免开发建两套实体）

| 需求原文术语 | 本项目实体 | 说明 |
|---|---|---|
| 亲密度 | = **满意度 S**（ANIM-16/14，单只独立 0–100） | 语料触发档位**直接复用 §1.4 三档**（低/中/高），不新增数值实体 |
| 天气 | M11 季节随机天气 | 按 D6 定位**边缘辅助**：仅作低权重修饰，不作硬门槛 |
| 近期互动 | 当日 喂食/放风/陪玩 的类型与次数 | 由 M7/ANIM-13 行为事件驱动，本设计只消费其输出 |
| 时间/昼夜 | 北京时间 UTC+8 的时段 | 复用 ANIM-16 §2.2 时段定义 |

设计总原则：**任何时刻都必须能产出一条语料** → 规则语料是永不失效的兜底层（D5），AI 是叠加在其上的可选增强（P2）。

## 1. 分层架构（两层，兜底优先）

```
        ┌────────────────────────────────────────────┐
        │  触发层：上下文键 = (档位 × 昼夜 × 天气 × 互动)  │
        └───────────────┬────────────────────────────┘
                        │ 查候选池 → 去重 → 选一条
        ┌───────────────┴────────────────────────────┐
Layer1  │  规则语料（P0 兜底 + P1 条件触发，默认常开）       │  ← 永不失效
Layer2  │  AI 语料（P2 灰度，默认关；命中则优先，失败回落 L1）│
        └────────────────────────────────────────────┘
```

- **Layer1 规则语料**：首发必用，分「兜底池（P0）」与「条件池（P1）」。
- **Layer2 AI 语料**：默认 `feature_flag = false`；开启且命中配额时优先采用，否则/失败时**无感回落 Layer1**。
- AI 只**增强表达多样性**，不改变触发条件、去重规则与满意度/评分数值。

## 2. 首发规则语料兜底方案

### 2.1 两类触发（先分清楚，避免"刷同一句"与"没话说"）

| 类型 | 触发时机 | 优先级 | 是否依赖外部条件 |
|---|---|:--:|:--:|
| **即时反馈语料**（兜底） | 绑定后首次进入牢房；每次 喂食/放风/陪玩 完成后 | **P0** | 否（必须命中） |
| **环境/主动语料**（条件触发） | 进入牢房、切换地图、定时/挂机展示等非即时反馈点 | **P1** | 是（受 §2.2 矩阵约束） |

> 兜底含义：即时反馈语料即使所有条件池去重后为空，也必须能出（走性格兜底池），保证"互动必有回应"。

### 2.2 触发条件矩阵（P1 条件语料）

**上下文键** = `(满意度档位 tier × 昼夜 daypart × 天气 weather × 互动上下文 interaction)`，查对应候选池。

维度取值（全部对齐基线）：
- `tier`：低(0–29) / 中(30–69) / 高(70–100)（ANIM-16 §1.4）
- `daypart`：早 / 午 / 晚 / 夜（对齐 §2.2：白天 10–22、夜间 22–07）
- `weather`：晴 / 雨 / 阴 / 雪…（M11 季节池，**低权重**）
- `interaction`：喂食 / 放风 / 陪玩 / 无（当日最近一次互动类型，取值对齐 ANIM-13 `/api/interaction` 的 `feed/play/exercise`）
- **近期互动频率**（修饰加权）：近 3 日互动频次高/低 → 影响"想念/抱怨冷淡"类文案加权

矩阵不穷举 `tier×daypart×weather×interaction` 全笛卡尔积（量大），而是**分层命中 + 回退**：

1. 先精确查 `tier × daypart`（核心二维）；
2. 若命中池去重后为空 → **放宽**到 `tier`（单维）→ 再放宽到**性格通用兜底池**（无条件）；
3. `weather` / `interaction` / 近期频率作为**加权修饰**（提升该子集权重），不作为硬筛选，确保"边缘"定位（D6）不被放大。

示例（性格=猫·关系户，仅示意）：

| 上下文键 | 候选池 | 文案方向示例 |
|---|---|---|
| tier=高 & daypart=夜 | 猫-性格-高档-夜 | "（叼着罐头看你）今晚多待一会儿？" |
| tier=低 & daypart=早 & interaction=喂食(厌恶食物) | 猫-性格-低档-喂食修正 | "（把罐头推开）……又给我这个？" |
| 兜底（任意） | 猫-性格-通用 | "（打了个哈欠，尾巴轻甩）" |

### 2.3 同条件基础去重策略（P0，验收硬指标）

- **去重键**：per-animal 维护**最近已播语料 ID 队列**（滑动窗口，默认最近 **20 条**）。
- **同上下文键 TTL**：同一 `上下文键` 内 **24h（对齐日切 UTC+8）不重复同一句**（记录 `context_key → {item_id: last_ts}`）。
- **池耗尽回退**：条件池去重后为空 → 按 §2.2 第 2 步逐级放宽到性格通用兜底池，**保证任意上下文必产出 ≥1 条**。
- **兜底池**：每只动物一个无条件"性格通用池"，是所有条件池的最终回退。
- **数据结构（服务端）**：
  ```
  last_played[animal_id]      : deque[item_id]   # 长度 ≤20，去重队列
  ctx_last_ts[animal_id][ctx_key][item_id] : ts   # 同键不重复，TTL=24h
  ```
- 去重窗口/TTL 为调参值，随语料总量增大可上调（见 §7 风险）。

## 3. 语料库结构与性格语料集组织（数据格式，供 M7/M8 开发）

### 3.1 语料实体 `corpus_item`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一 ID |
| `animal_id` / `species_id` | string | 归属：性格语料集用 `animal_id`，物种通用池用 `species_id` |
| `text` | string | 文案正文 |
| `source` | enum | `rule` / `ai`（AI 灰度生成入库，与规则同池） |
| `pool` | enum | `universal`(物种通用) / `personality`(性格) |
| `tags` | object | 条件标签（见下）；无标签=兜底 |
| `weight` | number | 池内加权（喜/厌/态度偏好调权，默认 1.0） |
| `valid_from` / `valid_to` | ts | 可用窗口（TTL/版本），支持热更上下线 |

### 3.2 条件标签 `tags` schema（对齐 §2.2 维度）

```
tags: {
  tier:      "low"|"mid"|"high"|null,
  daypart:   "morning"|"noon"|"evening"|"night"|null,
  weather:   "sunny"|"rainy"|"overcast"|"snow"|null,
  interaction:"feed"|"play"|"walk"|null,   // 对齐 ANIM-13 action 取值
  recent:    "active"|"idle"|null        // 近3日互动频率修饰
}
// 任一为 null = 该维度不约束；全 null = 兜底语料
```

### 3.3 语料集分层（与 ANIM-16 §1.5 性格参数联动）

- **物种通用池（universal）**：跨性格共享，最低成本兜底，首发每物种少量即可。
- **动物性格语料集（personality）**：per-animal，文案风格与命中加权**由该动物性格参数决定**——喜/厌（对齐 §1.5 喜欢/讨厌）、态度偏好（如"关系户猫拒绝早点点名"）映射为 `interaction`/`recent` 标签的 `weight` 与专属文案。
- 性格参数（k/d/floor/喜厌）来自 ANIM-16 §1.5 配置表，语料侧只**消费**，不重复定义数值。

### 3.4 配置表（服务端，全部热更，不硬编码）

| 表 | 内容 |
|---|---|
| `corpus_item` | 语料条目（§3.1） |
| `corpus_condition_tag` | 条件标签字典/取值 |
| `corpus_dedup_policy` | 去重窗口长度(20)、同键 TTL(24h)、回退层级顺序 |
| `corpus_ai_quota` | AI 每日上限（§4，P2） |

### 3.5 JSON 示例（供 M7/M8 落地）

```json
{ "id":"corpus_cat_001","animal_id":"cat_relater","species_id":"cat",
  "text":"（叼着罐头看你）今晚多待一会儿？","source":"rule","pool":"personality",
  "tags":{"tier":"high","daypart":"night","weather":null,"interaction":null,"recent":null},
  "weight":1.0,"valid_from":null,"valid_to":null }
{ "id":"corpus_cat_010","species_id":"cat","text":"（打了个哈欠，尾巴轻甩）",
  "source":"rule","pool":"universal","tags":{"tier":null,"daypart":null,"weather":null,"interaction":null,"recent":null},
  "weight":1.0,"valid_from":null,"valid_to":null }
```

### 3.6 语料在接口中的暴露（供 M8 / 服务端实现，接口契约）

> 服务端权威：上下文键计算、查池、去重、回退、AI 配额**全在服务端**；客户端只渲染返回的 `text`。字段名/端点为**建议契约**，服务端实现时按 api.md 约定与客户端开发工程师同步（接口契约变更由服务端同步客户端）。

- **即时反馈语料（P0 兜底，必出）**：`POST /api/interaction` 响应**新增 `corpus` 字段**（互动成功后随结果返回，供「语料气泡」展示，对齐 ANIM-13 §7.2 展示位）：
  ```json
  { ..., "ok": true, "deltaS": 6, ...,
    "corpus": { "text": "（把罐头推开）……又给我这个？", "source": "rule", "itemId": "corpus_cat_001" } }
  ```
- **环境/主动语料（P1 条件触发）**：进入牢房/地图时随 `GET /api/animal` 返回一条，或新增 `GET /api/corpus?animalId=&scene=enter`（scene=enter/map/timed）。上下文键由服务端按当前 档位/昼夜/天气/最近互动 计算并回退。
- 去重状态（`last_played` / `ctx_last_ts`，§2.3）落服务端（mock 期可用内存 + `X-Mock-Now` 覆盖时钟，对齐 ANIM-13/ANIM-16 的 UTC+8 权威时钟约定）。
- AI 语料命中时 `source:"ai"` 透传（供埋点/回滚），文案结构与规则语料一致。

## 4. AI 生成的可选增强/灰度方案（P2，默认关）

> 定位：AI 只**增强表达多样性**，触发条件/去重/兜底仍由 Layer1 规则层负责（AI 失败不影响"总有话说"）。首发**默认关**。

### 4.1 生成方式（离线批量，非实时逐条）
- **云端 LLM 离线/异步批量预生成** → 生成文案入库为 `corpus_item(source=ai)`，与规则语料**同池、同触发、同去重**。
- 优点：低延迟、低成本、无实时抖动；上线时玩家拿到的都是**已入库、已过校验**的文案。
- 生成侧在**每日批量窗口**（如 02:00 日切后）按"当日预计需求条数"生成，避免过量生成浪费成本。

### 4.2 触发频率与成本控制（三重控本）
| 层 | 限制 | 默认（调参值，可热更） |
|---|---|---|
| 每只动物 | 每日 AI 语料条数上限 N | **5 条/日/只** |
| 账号级 | 每日 AI 语料总上限 M | **20 条/日/账号** |
| 生成侧 | 批量按"预计需求"生成，不超额 | 与 N×在绑动物数 对齐 |
- 消耗侧：**当日 AI 配额用尽 → 自动回落规则语料池**（无感切换），不会因超量而中断或刷同一句。

### 4.3 开关与回退机制
- **特性开关** `feature_flag: ai_corpus.enabled`：全局 / 灰度用户群 / 动物级**三级**，默认 `false`，热更即时生效。
- **灰度放量**：白名单 → 百分比分桶 逐步放量；可即时关断止损。
- **回退触发**：开关关 / 生成失败 / 配额耗尽 / 校验不通过 → 回落 Layer1 规则语料，玩家无感知。
- **质量护栏（入库前过滤）**：敏感词、长度、**人设一致性**（与该动物性格参数不冲突）；保留 `source=ai` 标记，可按版本回滚。

### 4.4 边界（非目标）
- 首发 AI **默认关**；不进核心评分路径；不改变满意度/评分数值；模型选型留待 P2 灰度阶段 spike（本设计不锁）。

## 5. P0 / P1 / 灰度 优先级标注

| 优先级 | 内容 | 说明 |
|---|---|---|
| **P0（首发必做兜底）** | 语料实体+结构（§3）、绑定首次/互动后**即时反馈兜底语料**（`/api/interaction.corpus`）、物种通用池+性格兜底池、基础去重（同句不刷，§2.3） | 保证"总有话说 + 不刷同一句" |
| **P1（首发条件触发）** | 满意度档位×昼夜 触发矩阵（§2.2）、近期互动条件、天气条件（边缘/低权重）、候选池加权 + 热更配置表 | 让语料"有变化、有性格" |
| **P2 / 灰度（默认关）** | AI 语料生成、特性开关/灰度分桶、每日条数上限（§4）、离线批量生成、质量护栏 | 首发不含 AI 默认开启 |

## 6. 验收标准（对齐 M8 定稿判据）
1. **条件触发正确语料**：给定上下文键能命中预期候选池（tier×daypart 精确命中，weather/interaction 加权）。
2. **同条件去重不刷同一句**：同一上下文键 24h 内不重复同一句；滑动窗口 20 条内不重复。
3. **兜底永不空**：任意上下文（含所有条件池去重后为空）必能产出 ≥1 条（回退到性格通用池）；`/api/interaction` 成功响应必带 `corpus.text`。
4. **AI 默认关/灰度可控且限频**：flag 默认 false；开启后 ≤5 条/日/只、≤20 条/日/账号；配额尽自动回落规则池；灰度可即时关断。
5. **可热更**：语料条目、条件标签、去重参数、AI 配额均走配置表，不硬编码。

## 7. 风险与改进建议
- **天气定位（D6 边缘）**：天气仅作低权重加权修饰，不作硬门槛，避免与"低玩法影响"定位冲突；如嫌首发复杂，可延后天气到纯"档位×昼夜×互动"。
- **术语统一**：亲密度=满意度 S，复用 §1.4 三档，避免开发两套实体。
- **AI 成本/延迟**：离线批量 + 每只/账号双重每日上限 + 灰度分桶三重控本，可即时止损。
- **去重窗口 vs 语料量**：首发语料量小，20 条滑窗 + 24h TTL 足够；后续扩量建议改为"池覆盖率"策略（按池规模动态设窗口）。
- **依赖 ANIM-13**：互动反馈语料的具体触发点/时点已对齐 ANIM-13 `/api/interaction`（done）；`interaction` 标签取值对齐其 action，不改锁逻辑。
- **调参预留**：语料条数、去重窗口、TTL、AI 配额均热更，上线后按"同句重复率/玩家反馈"迭代。

## 8. 已定稿结论（v1.0）
1. **AI 每日上限**：5 条/日/只、账号级 20 条/日（首版调参值，可热更）。
2. **去重参数**：滑动窗口 20 条 + 同上下文键 TTL 24h（对齐日切 UTC+8）。
3. **天气**：纳入 P1 但**低权重**（D6 边缘）；若首发嫌复杂可先做"档位×昼夜×互动"，天气延后（不阻塞 P0/P1 主体）。
4. **AI 模型选型**：留待 P2 灰度阶段做 spike，本设计不锁（默认关）。
5. **接口契约**：`/api/interaction` 增 `corpus` 字段（P0 必出）；`/api/animal`（或 `/api/corpus`）承载环境/主动语料（§3.6）。服务端实现时同步客户端。

**本设计作为 M8 语料系统设计定稿 v1.0，供 M7/M8 开发；数值/参数首版可热更。**
